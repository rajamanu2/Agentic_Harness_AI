ForgeOS configuration lives in two scopes:

- **Global configuration** in `~/.forgeos/` (applies globally across all ForgeOS applications, including IDE, CLI, and SDK)
- **Project configuration** in `.forgeos/` (applies only to the current workspace)

## Configuration Directory Layout

ForgeOS stores shared configuration across a few well-known locations. The primary root is `~/.forgeos/`, with structured app state under `~/.forgeos/data/`:

```text
~/.forgeos/
  data/
    settings/
      providers.json           # API keys and provider configuration
      global-settings.json     # Global settings
      forgeos_mcp_settings.json  # MCP settings
    teams/                     # Team state
    sessions/                  # Session data
    db/                        # SQLite databases (for example cron.db)
    workflows/                 # Global workflows
  rules/                       # Global rules
  hooks/                       # Global hooks
  skills/                      # Global skills
  agents/                      # Global agent definitions
  plugins/                     # Global plugins (.js, .ts)
  cron/                        # Global cron specs
```

Additional global search paths supported by the code:

```text
~/Documents/ForgeOS/
  Rules/                       # Additional global rules
  Hooks/                       # Additional global hooks
  Plugins/                     # Additional global plugins
  Workflows/                   # Additional global workflows
```

Project-level configuration lives in `.forgeos/` at your repository root:

```text
.forgeos/
  rules/                       # Project rules
  skills/                      # Project skills
  hooks/                       # Lifecycle hooks
  agents/                      # Project agent definitions
  plugins/                     # Project plugins
  cron/                        # Workspace cron specs
```

Notes:

- Global provider settings, global settings, and MCP settings are stored under `~/.forgeos/data/settings/`.
- Global workflows resolve from `~/.forgeos/data/workflows/`.
- Global rules, hooks, skills, agents, plugins, and cron specs resolve directly under `~/.forgeos/`.
- Rules, hooks, plugins, and workflows may also be discovered from `~/Documents/ForgeOS/` for compatibility.

## What Goes Where?

- Use **global (`~/.forgeos/`)** for defaults shared across all ForgeOS applications (IDE, CLI, SDK) on your machine.
- Use **project (`.forgeos/`)** for team-shared behavior that should travel with the repo.

Commit `.forgeos/` files you want to share with your team. Keep secrets out of the repo.

## Configure Through the CLI

Use the interactive config UI:

```bash
forgeos config
```

From there, you can view/edit:

- Settings (global + workspace)
- Rules
- Skills
- Hooks

## Useful Configuration Commands

Use a custom configuration directory:

```bash
forgeos --config /path/to/custom/config "your task"
```

Or via environment variable:

```bash
export FORGEOS_DATA_DIR=/custom/path/to/forgeos
forgeos "your task"
```

View CLI logs when troubleshooting:

```bash
forgeos dev log
```

## Environment Variables

| Variable | Description |
|----------|-------------|
| `FORGEOS_DATA_DIR` | Custom data directory (replaces `~/.forgeos/data/`) |
| `FORGEOS_HUB_ADDRESS` | Override hub address (default: `127.0.0.1:25463`) |
| `FORGEOS_SESSION_BACKEND_MODE` | Force backend mode (`local`, `hub`, `remote`, `auto`) |
| `FORGEOS_SANDBOX` | Enable sandbox mode |
| `FORGEOS_SANDBOX_DATA_DIR` | Sandbox session storage directory |
| `FORGEOS_HOOKS_DIR` | Additional hooks directory |
| `FORGEOS_COMMAND_PERMISSIONS` | JSON policy restricting shell commands |

### FORGEOS_DATA_DIR

```bash
export FORGEOS_DATA_DIR=/custom/path/to/forgeos
forgeos "your task"
```

### FORGEOS_COMMAND_PERMISSIONS

Restrict which shell commands ForgeOS can execute:

```bash
export FORGEOS_COMMAND_PERMISSIONS='{"allow": ["npm *", "git *"], "deny": ["rm -rf *"]}'
```

Format:

```json
{
  "allow": ["pattern1", "pattern2"],
  "deny": ["pattern3"],
  "allowRedirects": true
}
```

Rules:

- `deny` overrides `allow`
- If `allow` is set, commands not matching `allow` are denied
- `allowRedirects` controls shell redirects (`>`, `>>`, `<`), default `false`

## Security Notes

<Warning>
Only use rules, hooks, skills, and plugins from sources you trust.
</Warning>

Hooks and plugins can execute code. Review them like any other executable artifact before adding them globally or to a project.
